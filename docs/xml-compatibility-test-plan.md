# XML Compatibility Test Plan

This document describes the test strategy for ensuring `matsim-models` correctly reads and writes MATSim XML files across versions.

## Overview

The goal is to ensure that:
1. `matsim-models` can read XML files produced by MATSim 2025.0
2. `matsim-models` can write XML files that MATSim 2025.0 can read
3. Round-trip (read -> write -> read) preserves semantic equality
4. Schema validation passes for all generated XML

## Test Categories

### 1. Read/Write/Read Round-Trip Tests

**Purpose**: Verify that reading a file, writing it back, and reading again produces semantically equivalent models.

**Coverage**:
- network.xml
- population.xml
- transitSchedule.xml
- facilities.xml
- lanes.xml
- config.xml
- vehicles.xml
- households.xml
- events.xml

**Test Pattern**:
```java
@Test
void roundTrip_network() {
    // Read original
    Network original = new NetworkXmlReader().read(Path.of("fixtures/network.xml"));
    
    // Write to new file
    Path tempFile = tempDir.resolve("output.xml");
    new NetworkXmlWriter().write(original, tempFile);
    
    // Read back
    Network roundTripped = new NetworkXmlReader().read(tempFile);
    
    // Verify semantic equality
    assertEquals(original.getNodes().size(), roundTripped.getNodes().size());
    assertEquals(original.getLinks().size(), roundTripped.getLinks().size());
    // ... additional assertions
}
```

**Status**: Implemented in `NetworkXmlTest`, `PopulationXmlTest`, `TransitScheduleXmlTest`, etc.

### 2. Schema Validation Tests

**Purpose**: Ensure generated XML validates against MATSim XML schemas.

**Coverage**: All XML types with corresponding XSD schemas.

**Test Pattern**:
```java
@Test
void validatesAgainstSchema() {
    Network network = new Network();
    // ... populate network
    String xml = new NetworkXmlWriter().writeToString(network);
    
    Schema schema = XmlSupport.loadSchema("schemas/network.xsd");
    assertTrue(XmlSupport.validate(xml, schema));
}
```

**Status**: Implemented in `XmlSchemaValidationTest`.

### 3. Large Events Streaming Test

**Purpose**: Verify that large event files (millions of events) can be streamed without OOM errors.

**Test Pattern**:
```java
@Test
void streamsLargeEventsFile() {
    // Generate large events file
    Path largeFile = generateLargeEventsFile(1_000_000);
    
    // Stream and count
    long count = new EventsXmlReader().stream(largeFile)
        .count();
    
    assertEquals(1_000_000, count);
}
```

**Status**: To be implemented.

### 4. Application Integration Test Plan

**Purpose**: Verify that `matsim-models` works correctly within application workflows.

**Test Scenarios**:
1. Load network from application project -> modify -> save -> verify
2. Load population -> apply scenario changes -> save -> verify
3. Load config -> update parameters -> save -> verify MATSim accepts it
4. Full workflow: network + population + transit + config -> run MATSim

**Test Pattern**:
```java
@Test
void cityModelerWorkflow_networkModification() {
    // Load network from application project
    Network network = new NetworkXmlReader().read(cityModelerProject.resolve("network.xml"));
    
    // Apply modification (e.g., add new link)
    network.addNode(...);
    network.addLink(...);
    network.postProcess();
    
    // Save
    new NetworkXmlWriter().write(network, outputDir.resolve("modified-network.xml"));
    
    // Verify MATSim can read it (via MatsimProcessRunner)
    MatsimProcessRunner runner = new MatsimProcessRunner(config);
    runner.setNetwork(outputDir.resolve("modified-network.xml"));
    runner.dryRun(); // Just validate input
}
```

**Status**: To be implemented in application test suite.

### 5. Cross-JVM MATSim Loading Test

**Purpose**: Verify that XML generated by `matsim-models` can be loaded by real MATSim in a separate JVM.

**Test Pattern**:
```java
@Test
void matsimLoadsGeneratedXml() throws Exception {
    // Generate XML with matsim-models
    Network network = new Network();
    // ... populate
    Path generatedFile = tempDir.resolve("network.xml");
    new NetworkXmlWriter().write(network, generatedFile);
    
    // Run MATSim in separate process to load it
    ProcessBuilder pb = new ProcessBuilder(
        "java", "-cp", matsimClasspath,
        "com.citymodeler.matsim.test.MatsimNetworkLoader",
        generatedFile.toString()
    );
    Process process = pb.start();
    
    // Verify success
    int exitCode = process.waitFor();
    assertEquals(0, exitCode);
}
```

**Helper Class** (`MatsimNetworkLoader.java`):
```java
package com.citymodeler.matsim.test;

import org.matsim.core.network.io.NetworkReader;
import org.matsim.core.scenario.ScenarioUtils;

public class MatsimNetworkLoader {
    public static void main(String[] args) {
        String networkFile = args[0];
        var network = ScenarioUtils.createScenario().getNetwork();
        new NetworkReader(network).readFile(networkFile);
        System.out.println("Loaded " + network.getNodes().size() + " nodes");
        System.exit(0);
    }
}
```

**Status**: To be implemented.

## Future Testing

### MATSim Version Matrix

Test against multiple MATSim versions:
- 2025.0 (current)
- 2024.x (previous)
- 2023.x (older)

This requires maintaining multiple fixture sets or ensuring backward compatibility.

### Property-Based Testing

Use property-based testing (e.g., jqwik) to generate random but valid MATSim XML and verify round-trips:

```java
@Property
void roundTrip_anyNetwork(@ForAll("networks") Network network) {
    String xml = new NetworkXmlWriter().writeToString(network);
    Network roundTripped = new NetworkXmlReader().readString(xml);
    assertEquals(network.getNodes().size(), roundTripped.getNodes().size());
}
```

### Performance Benchmarks

Track parsing and writing performance:
- Time to read 1M node network
- Time to write 100K person population
- Memory usage during streaming

## Test Execution

Run all tests:
```bash
mvn clean verify
```

Run specific test class:
```bash
mvn test -Dtest=NetworkXmlTest
```

Run with coverage:
```bash
mvn clean test jacoco:report
```

## Reporting

Test results are available in:
- `target/surefire-reports/` - JUnit XML reports
- `target/site/jacoco/` - Code coverage report

CI runs tests on every push and PR to `main` and `develop` branches.

## Maintenance

When MATSim releases a new version:
1. Update fixture files to match new schema
2. Add new test cases for schema changes
3. Update compatibility matrix in README
4. Consider semantic versioning for `matsim-models`
